# Validation attempts and limitations

All source corrections were committed before the final tested source `b14da3d`. No assertion was weakened and no retry policy was added.

- Baseline full verbose run: 267 files / 1,787 tests passed in 177.92 s. The earlier stopped silent run was not reproduced as a hang.
- First integrated full run: 11 files / 13 expectations failed because schema 94 adds a profile-scoped table and two explicit channels. Exact versions/counts/registries were updated, and both commands joined the secret-leak sweep; focused and subsequent full suites passed.
- An early focused migration run exposed three more old manifest/future-version expectations, corrected with the new ordered migration retained.
- The initial custom native fixture imported `strategyDecisionId` from storage instead of core. It was corrected; no product code changed for that import. Later fixture failures came from not selecting the existing Recovery category, then assuming a hash-only loadFile navigation created a new document. The fixture now selects the category and fully reloads controlled loading/error scenarios. These were harness corrections, not relaxed state assertions.
- Visual inspection found an actual product defect in the newly added unstyled hash inputs. Existing field styling and a constrained layout were applied and verified in the final bounded visual pass.
- The pre-fix Activity build demonstrably lost detail focus when a delayed route-focus callback ran. The same controlled ordering passes after the production fix; no passing retry substitutes for reproduction.
- Initial benchmark instrumentation attempted a nonexistent `webContents.getProcessMemoryInfo`; it was corrected to the installed Electron API `app.getAppMetrics` for the renderer PID. The original console failure is in the task history; its first working-path JSON was superseded before being archived, so no raw initial receipt is claimed here.
- Shared-browser preliminary runs showed approximately four seconds in the first sessionStorage read. CPU profiles and a private-browser comparison established a benchmark isolation defect. The final harness uses disposable browser/session storage, and old measurements are labelled as shared-data/confounded, not used as acceptance.
- Preliminary long runs were deliberately stopped when their source or harness was superseded. Their partial minute logs are retained. They do not establish a completed thirty-minute soak. Two fixture Electron processes did not exit on SIGTERM; only those identified owned processes were force-closed before the isolated final run.
- One stock performance-gate attempt failed with ERR_FILE_NOT_FOUND and mount timeout because two locally orchestrated commands both rebuilt/cleared dist/renderer concurrently. The failure log is retained. Build/execution were separated and the unchanged gate then passed, including the intentionally failing 250 ms sensitivity control. Existing CI jobs have isolated checkouts/serialized steps; no CI policy change was inferred from this local orchestration error.
- The first custom news-chain harness used a manifest hash as the archive directory. The archive format uses news/datasetHash; correcting the harness path produced a verified deterministic chain. The initial failure log is retained.
- Boundary review of the new location handler found generic SQLite errors grouped with filesystem-validation errors. The filesystem code list was narrowed. An injected SQLite insertion failure now returns uncertain completion and leaves history unchanged; this production correction and regression are in 0202177.
- Integration review found that clone exclusion omitted the newly added immutable location rows. A valid clone fixture failed before the fix and passed afterward; exclusion now removes location authority before source associations/permissions, preserves source bytes, and requires a separate clone association. Existing clone suites pass. The first new test attempt used an invalid destination filename; that harness error is retained separately from the valid-input regression.
- Final lint found 501 counted lines in the channel contract test. Adjacent channel entries were formatted together without changing assertions. A comment-only attempt did not affect the counted-line rule and is retained.
- Two native recheck commands initially ran from desktop, which does not directly depend on these native packages. They failed package resolution before loading a native module; the same checks ran successfully from adapters/storage, their actual dependency owners.
- The first 271-file suite overlapped a test-only formatting commit (no assertion or application-byte changes). Its log remains supplementary. A new final run held b14da3d fixed at both ends and passed 271 files / 1,815 tests in 158.56 seconds; exact first-output/completed-file times are recorded. That final run overlaps approximately minutes 5–8 of the synthetic retention workload.
- Staged evidence diff whitespace check reports trailing spaces from Vite and extra final blank lines from Vitest raw logs. Captured log bytes are retained rather than silently normalized. Source/non-log documentation diff checks are reported separately; this is not a production-source whitespace failure.
- Historical intermediate package identity/checksum receipts are retained, but superseded generated DMG/ZIP bodies at the standard release filenames were not retained. Final b14da3d package bodies have separate retained copies and matching hashes; old receipts do not imply old binary availability.
- No source changes follow the final tested revision. Documentation/evidence updates do not change the application source hash. No actual profile migration/restore, broker command, paid provider, credential access, study transition, PR merge or publication occurred.

Windows, actual-profile/representative archive/installed recovery, real-data lag, natural authorized news usefulness, human VoiceOver/high contrast, research enrollment/elapsed observations and release gates remain open where not established by their own evidence.

## Source limits and deliberate unavailable states

| Source/case | Verified capability | Evidence still required |
|---|---|---|
| Local paper | Explicit immutable funding, ledger/fill conservation and an actual common-time quote cut can establish economic opening and forward observations | Rounded old daily rows without individual price times do not become exact marks; unexplained reconciliation rows block dependent flow coverage |
| Coinbase | Schema-2 normalized financial evidence remains unchanged; separately versioned membership/counterparty/fee envelope, stable provider event identities and duplicate fill links are retained | Portfolio identity, complete account membership, financial effective times, transfer purpose/receipt and a coherent complete valuation cut must be independently supported; existing bounded history alone is insufficient |
| Alpaca paper | Account/environment verification, bounded activity/order acquisition, final historical total-equity marks and explicit fee/interest records are durable | Current account cash reconciliation alone does not prove a coherent total-equity cut; date-only CSD/CSW and ambiguous JNLC cannot provide invented instant flow marks or confirmed user receipt |
| Robinhood | Existing observed balances remain available | No adequate capital-flow acquisition exists in P1; verified account performance stays unavailable |
| Tax basis | Existing tax-lot reports retain their original interpretation | Account-scoped lot ownership/basis is not independently proven; scoped realized/unrealized metrics remain unavailable even when economic P&L is supported |
| Fees and transfers | Supplied exact debit, credit, fee and receipt legs remain distinct; economic equity counts costs once | Unknown splits, non-USD fee prices or receipt evidence block only dependent attributions when total economics is independently supported |

Unknown/ambiguous funding blocks the affected period. Pending status does not establish a completed contribution or receipt. Supported status transitions append revisions; conflicting values without authoritative correction remain unresolved. Connection removal, restore and profile duplication do not mint new history, authority or a fresh economic account. New captures retain the existing epoch; loss history is not reset.

## Independent regression fixtures

Expected values were hand specified, then checked against production pure functions and persisted projections.

| Fixture | Required result |
|---|---|
| Equity $500 remains $500 while cost basis changes $500 → $300 | No capital flow; economic P&L $0 and TWR 0% |
| $500 opening + $500 deposit = $1,000 after one year, with exact flow-time marks | P&L $0; TWR and annualized TWR 0% |
| $1,000 opening − $500 withdrawal = $500, with exact marks | P&L $0; TWR and daily drawdown 0% |
| Two endpoint observations two days apart, no flows | Supported endpoint return; daily risk metrics unavailable, no bridged daily sample |
| $102 account debit, $100 confirmed receipt, $2 fee | P&L −$2; outflow $100; fee attribution $2; no second fee deduction |
| Unknown acquisition basis, independently supported opening/flows/end | Economic P&L available; affected lot P&L unavailable |
| Supported period flows but missing terminal asset price | Flow totals remain available; dependent equity/P&L/returns unavailable |
| Complete capital redemption compared with a genuine 100% loss | Redemption is neutral unit redemption; real zero-NAV loss remains −100%; later funding is not stitched across an invalid denominator |
| Late authoritative correction | New immutable report links its predecessor; the old report and exact input facts still reproduce unchanged |

Neutrality covers $50, $100, $250, $500, $1,000, $2,500, $5,000, $10,000 and $100,000. Fast-check event sequences supplement independent fixtures with conservation, idempotency and flow-neutrality properties. Tests also cover internal transfers, manual activity, non-USD missing valuation, duplicate pages/representations, pending transitions, conflicts, boundary uncertainty, missing daily marks, unique IRR/no root/unproven uniqueness, wrong environment, credential rotation and lifecycle transitions.

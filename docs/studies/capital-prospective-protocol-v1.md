# Capital prospective protocol v1 — software capability

This document describes `capital-prospective-study-v1`. It is not a study registration, an owner approval, elapsed market evidence, a research result or paper authorization. The saved [P7 plan](../implementation/small-portfolio-p7-implementation-plan-2026-10-24.md) and complete [P0–P7 roadmap](../implementation/small-portfolio-profit-policy-plan-2026-10-23.md) remain authoritative. P5-H, P6-G/H and P7-H–J remain pending.

The owner must supply a finite reviewed design before its future UTC start, exact runtime/protocol/rights/custody/exposure references, future development/final windows, all nine independent USD openings, explicit funding/expenses/yield, native rules and fee assumptions, signal/control/policy inventories, selection weights, power/applicability/rolling/uncertainty gates and bounded resources. No dates, capital account, financial permissions or favorable thresholds are installed by default. Adoption of a P5 hypothesis still requires P5-H.

A separately stored prospective search declaration has no dataset hash and is not verified historical evidence. It counts in the global trial inventory. Source protocol and registration hashes are known before acquisition; actual future frames are content-addressed only after capture. The authoritative inventory includes historical trials and shared consumption claims; a new empty profile cannot establish global completeness.

## Observation convention

V1 uses UTC daily cuts. A frame provides the just-completed closing mark at the slot and a separately timestamped attainable quote after that slot, causal completed history, observed native rules, provider/environment and acquisition provenance. Decisions made from that acquisition can execute only at a strictly later acquired daily quote, with the declared decision delay. This is an explicit delayed shadow execution model, not an assertion of first-tick fills, unknown intrabar ordering, queue priority or actual broker execution. Final/development terminal cuts value the existing book without a post-cut trade.

A slot is eligible only inside the frozen source completion/lateness interval. The current collector obtains one current slot under an explicit process-local permit, host generation, unique collector nonce and bounded renewable lease. Acquisition occurs outside the transaction; current ownership and all financial checkpoints are checked again inside the atomic append. There is no historical catch-up. Restart, restore or host/profile change requires explicit reviewed continuation and retains every missed date and prior loss.

V1's correction rule is conservative quarantine: conflicting/provider-corrected evidence retains the old fact and original report, invalidates the affected slot and appends a superseding unavailable report when applicable. It does not choose truth by arrival order, repair eligibility retrospectively, reset a clock or reopen a consumed interval. A new reviewed, genuinely future design is required where necessary.

Observed market/rule evidence is distinct from modeled fills, costs, funding, reserves and receipts. Shadow observations never write the verified capital-account ledger, actual P6 balances, OMS orders/fills or provider APIs. Real paper action count is always zero. Existing gates requiring actual settled activity stay unsatisfied by shadow counts.

P1 calculations retain exact metric-specific availability. Principal and explicitly declared profit receipts remain separate; unexplained withdrawals are not profits. Pending outflows retain a supported receivable until confirmation. Reserve/tax cash stays inside managed equity once; H and assessed history survive release. Missing flow-time marks or ambiguous flow/fee ordering can leave TWR unavailable while independently supported economic dollar P&L remains visible. No curve is scaled from $100,000 to represent a small book.

## Assessment and final custody

Signal choice uses fixed primary capital weights, complete matched daily NAV, preregistered controls and conservative/doubled costs, chronological folds, DSR, stricter applicable PBO and frozen sample/action/rolling gates. Balances, paths and bootstrap replications are not independent alpha trials. Exposure-control weights are frozen reviewed calibration artifacts identified by the warmup exposure reference; the collector does not refit them on future outcomes.

Execution and reserve comparisons remain separate conditional policy assessments. Joint market paths rebuild all nine books, funding, costs, fees, yields and policy transitions rather than shuffling a distributed return curve. Finite samples, fixed universe, approximate paired basic-bootstrap coverage, effective blocks and tail replication limitations remain explicit. Resource exhaustion or insufficient path evidence yields unavailable, not a passing zero. No optimal share or scientific guarantee is inferred.

Final coverage exposes only outcome-independent metadata. Book values, positions, action counts and rankings remain sealed at the repository boundary. An owner freezes candidate or none after development terminal acquisition and before final start; none opens no final bodies. Candidate evaluation requires an elapsed complete final window, reviewed provenance and the existing shared durable holdout claim plus matching P7 attempt, atomically committed before financial reads. Only the frozen candidate and declared controls are then selected in SQL. Any later failure retains consumption. Exact completed receipt retrieval does not evaluate again.

An explicit independent paper review pins strategy, primary supported capital, universe, funding, risk policy, protocol, costs, horizon and validity. V1 validity is bounded by both the design's fixed post-window limit and a maximum one-day review interval. Corrections, revocation, expiry, changed runtime/cost/configuration or newly incomplete trial history withhold the proof. The P7 strategy namespace differs from the existing P6 TrendVol adapter. The existing P6 consumer does not supply the additional P7 configuration capability, so a P7 review cannot arm that adapter or impersonate old forward-edge evidence. A separately reviewed operational adapter is required for any future use.

## Explicit local workflow

After building the application, `node scripts/research-capital-prospective.mjs --help` lists bounded local reads and separate reviewed owner actions. No installed database is chosen by default. Reads open an explicitly selected current-schema database read-only. CLI never migrates, creates a profile, assigns host authority, registers a default design, changes dates or calls a provider.

For an owner action, explicitly select the active profile manifest, database, workspace, authoritative host and exact request JSON. `--prepare` prints the request/design/runtime/custody digests without executing it. A separate approval JSON must bind the action and digests, reviewer and authoritative exposure/history references. `--owner-reviewed` represents the local owner's deliberate invocation; an arbitrary renderer `actor` field is not accepted. The owner remains responsible for reviewing the evidence behind those references.

Start/continue require a bounded process duration and an explicit reviewed source directory. Each current slot's `<slotMs>.json` is a bounded acquisition export matching the frozen provider/protocol; local recording time comes from the collector. This is owner-attested acquisition evidence, not cryptographic proof from a provider. Rights, exporter integrity, availability and custody must be independently reviewed before actual H registration. Failed/missing exports do not backfill future coverage. The process drops its permit on exit; stored collection intent is never proof of a healthy collector. No automatic system service or scheduler enrollment is installed.

`assess-development` persists a permitted development assessment; normal `development` and report reads never materialize one. Freeze/final/review/revoke/correction each have exact operation receipts. Final inspection uses a separate reviewed owner capability only after the durable claim. Ordinary report reads accept explicit accessible report IDs and never open an unreviewed final body.
